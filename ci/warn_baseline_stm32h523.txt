# Regenerated from a REAL build (grbl/platform/PLAN.md Phase 1 fixed the
# TIM1-register-gap / spindle-PWM / handlers.c EXTI-model breakage that
# previously prevented arm-none-eabi-gcc from ever reaching this file list -
# the PREVIOUS version of this file was authored by code inspection before
# the build ever ran and is fully replaced here). Union of BUILD=DEBUG and
# BUILD=RELEASE logs - both produced the identical warning set. Command:
#   make -C grbl/platform/stm32h523 BUILD=<DEBUG|RELEASE> > build.log 2>&1

# The "config.h vs platform.h dual pin-map canon" entries that used to sit
# here (same 9 lines as stm32f103's baseline) were BUG #25, not harmless
# debt: SPINDLE_ENABLE_PIN/SPINDLE_DIRECTION_PIN/COOLANT_FLOOD_PIN genuinely
# disagreed in value between the two files, and hal_gpio_init() didn't even
# consume the pin macro for the affected pins here - it hardcoded raw
# literals that happened to match config.h's (now-deleted) values instead of
# platform.h's, with the direction pin additionally hardcoded onto the wrong
# GPIO port. The spindle enable relay's pin was configured as an output on
# one physical pin and driven (GPIO_BSET/GPIO_BCLR) on a different one.
# Baselining the warning instead of reading it hid a live wiring defect
# behind a green ratchet for as long as the entry sat here (and it sat here
# BECAUSE stm32f103's baseline already carried it - "same pattern already
# accepted" should have been the signal to fix the class, not repeat it) -
# see CONTRACTS.md #gpio-pin-map-single-owner. Fixed by making platform.h
# the sole owner of every pin/port/bit/mask and deriving hal_gpio_init()'s
# masks from it. Do NOT re-add any of these lines - if this class of warning
# reappears, a duplicate pin-map definition has come back and the ratchet is
# now supposed to fail on it.
#

# [-Woverflow]` (BUG #18 class, CONTRACTS.md #18). Root cause:

# the true compile-time constant is 15000000000, not 2115098112 (a real
# ~7.09x-too-fast stepper timing bug). Fixed at the source (common.mk now
