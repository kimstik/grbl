# warning set (same as stm32h523's baseline note). Command:

#   python3 ci/warn_ratchet.py --log build.log --emit

# Removed 2026-07-26: `stepper.c: ... integer overflow ... '1465032704'
# [-Woverflow]` (BUG #18 class, CONTRACTS.md's clock-constant-width
# section). Root cause:
# common/stm32/common.mk's F_CPU lacked a suffix wide enough for 96 MHz -
# the true compile-time constant is 5760000000, not 1465032704 (a real
# ~3.93x-too-fast stepper timing bug, not cosmetic). Fixed at the source
# (common.mk now uses ULL); do NOT re-add.
#
# The "config.h vs platform.h dual pin-map canon" entries that used to sit
# here (CONTROL_MASK/DIRECTION_MASK/LIMIT_MASK/PROBE_MASK/
# STEPPERS_DISABLE_MASK/STEP_MASK, all "redefined") were the numerically-
# benign half of BUG #25: every value here happened to match platform.h's
# (this port's config.h was hand-mirrored to platform.h, unlike f103/h523
# where SPINDLE_ENABLE_PIN/SPINDLE_DIRECTION_PIN/COOLANT_FLOOD_PIN actually
# disagreed and drove a real wiring defect). "Numerically benign today"
# is not "safe to baseline forever": a hand-mirrored duplicate is one
# unreviewed edit away from splitting exactly like its siblings did, and
# the compiler would not have warned about a *matching* redefinition drifting
# apart in a future edit that touched only one file's copy - the warning
# above only ever caught the fact of duplication, not a future divergence.
# Fixed by making platform.h the sole owner of every pin/port/bit/mask (see
# CONTRACTS.md #gpio-pin-map-single-owner) instead of relying on two files
# being kept in sync by hand. Do NOT re-add any of these lines - if this
# class of warning reappears, a duplicate pin-map definition has come back.
